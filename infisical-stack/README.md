# Infisical stack (BACKLOG #94 Phase 1)

Customer-facing AdminLM secret store. Bound to **127.0.0.1:8090** so the
operator's network can never reach the Infisical web UI directly — the
future Streamlit Secrets page (Phase 3) is the only operator surface.

## What this stack provides

- `infisical` — Infisical OSS backend, pinned to **v0.166.2** (released
  2026-10-07). NOT `:latest` (BACKLOG #86 lesson).
- `infisical-postgres` — Postgres 14 for Infisical's DB.
- `infisical-redis` — Redis 7 (with `--requirepass` enforced).

## Files

- `docker-compose.yml` — the 3-service compose.
- `.env.example` — placeholder env file (committed). Real `.env` is
  generated by `bootstrap.sh deploy_infisical_stack()` on first run and is
  NOT committed (gitignored).
- `README.md` — this file.

## Operator credentials

Live in `~/.hermes/secrets/infisical-operator.env` (chmod 600), populated
by `bootstrap.sh deploy_infisical_stack()`. Contents:

```
INFISICAL_POSTGRES_PASSWORD=...
INFISICAL_REDIS_PASSWORD=...
INFISICAL_AUTH_SECRET=...
INFISICAL_ENCRYPTION_KEY=...
INFISICAL_ADMIN_EMAIL=...
INFISICAL_ADMIN_PASSWORD=...
INFISICAL_ORGANIZATION_ID=...
INFISICAL_PROJECT_ID=...
INFISICAL_ADMIN_TOKEN=...   # machine identity token (root-level)
INFISICAL_BOOTSTRAP_DONE=true
```

## Idempotency

`deploy_infisical_stack()` is idempotent:
- On first run: generates secrets, writes `.env`, brings up the stack,
  polls `/api/status`, calls `POST /api/v1/admin/bootstrap`, creates the
  default project, writes operator creds file.
- On re-run: if `INFISICAL_BOOTSTRAP_DONE=true` AND `/api/status` returns
  200, the function is a no-op (skips generation, skips API calls).

## Verification

`bootstrap.sh verify_installation()` checks `curl http://127.0.0.1:8090/api/status`
returns 200 on the loopback interface.
